# Naming traps and weak slogans

Correct these before you cite them. Growth.Design one-liners are sometimes wrong.

| Label on the page | What it actually is | Do not |
|---|---|---|
| Spark Effect | Fogg **Ability** / Tiny Habits: smaller effort → more action. Fogg’s “Spark” is a *prompt that motivates* (high ability, low motivation). | Call a one-click CTA “Fogg Spark.” |
| Juxtaposition | GD’s line is proximity + similarity (grouping). Ad juxtaposition is side-by-side *comparison*. | Treat “near and similar = one unit” as juxtaposition. |
| Visual Anchors | Design craft: gaze landing spots. Not anchoring bias (first *number*). | Mix with price anchoring. |
| Miller’s Law | Miller 1956 slogan. Capacity is in **chunks**. Cowan: closer to **4±1** when rehearsal is blocked. Visible menus are recognition, not recall. | Cap nav at 7 items “because Miller.” |
| Group Attractiveness | GD line = **cheerleader effect** (Walker & Vul: a person looks better *in* a group). The paper titled GA-effect (van Osch) is “group > mean of members.” | Conflate the two. |
| Expectations Bias | Umbrella, not one study. Nearby: confirmation, placebo, mental models, observer-expectancy. | Cite it as a named experiment. |
| Availability Heuristic | Judge *frequency/probability* by ease of recall (Tversky & Kahneman 1973). Recency is one input. | Say “users prefer recent info.” |
| Decision Fatigue | Real: later choices get sloppier. **Ego depletion** and the parole-breakfast study failed replications (Hagger RRR 2016; Vohs multilab 2021; Danziger 2011 artifacts). | Cite willpower-as-glucose or the lunch-break judges story. |
| Backfire Effect | Worldview backfire (correction strengthens the myth) is **rare** (Wood & Porter 2019; Nyhan 2020). Persistence is usually ignore + decay. | Refuse to correct “because backfire.” |
| Pareto Principle | Concentration heuristic (Juran’s vital few). Not a cognitive bias. Split is not magically 80/20. | Delete the long tail new users need. |
| Tesler’s Law | Complexity is conserved; someone holds it. Tesler wanted **engineering** to absorb it. GD’s line is only the oversimplification half. | Hide price/permissions and call it Tesler. |
| Bandwagon vs Social Proof | Social proof = heuristic (copy others when unsure). Bandwagon = adoption begets adoption (also FOMO). | Use them as synonyms. |
| Halo vs Aesthetic-Usability | Halo = one trait spills to other traits. Aesthetic-usability = pretty → *feels* easier (Kurosu & Kashimura 1995). | “Pretty is more usable.” |
| Peak-End vs Serial Position | Peak-end = affective high/low + ending. Serial position = first/last of a bland list. | Treat any last item as a peak. |
| IKEA vs Endowment vs Sunk Cost | IKEA = labor that *finishes* raises value. Endowment = mere ownership. Sunk cost = staying because of past spend. | Use one name for all three. |
| Feedforward vs Feedback vs Signifier | Feedforward = consequence *before* click. Feedback = what just happened. Signifier = how this control works. | Call a toast “feedforward.” |
| Internal vs External vs Self-initiated trigger | External = cue in the world with the next step in it. Internal = feeling/memory. Self-initiated = *user-authored* prompt. | Treat all notifications as internal triggers. |

## Replication / overclaim list

Safe to use as design heuristics, but do not over-cite:

- Decision fatigue / ego depletion
- Worldview backfire
- Pygmalion classroom magnitudes
- “7±2 menu items”
- Fake-progress “labor illusion” as always increasing value (it can also feel slow)
